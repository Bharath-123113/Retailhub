# RetailHub Pull Request Checklist

## 1. Before Creating a Pull Request

- [ ] Changes are made in the correct feature branch.
- [ ] Code follows project naming conventions.
- [ ] No unnecessary files are included.
- [ ] No passwords, tokens, or secrets are committed.
- [ ] Documentation is updated.
- [ ] Required tests and validations are completed.

## 2. Pull Request Details

- [ ] PR title clearly explains the changes.
- [ ] PR description explains the purpose of the changes.
- [ ] Correct base branch is selected.
- [ ] Correct source branch is selected.
- [ ] Relevant reviewers are assigned.

## 3. Code Review

- [ ] Changed files have been reviewed.
- [ ] Review comments are addressed.
- [ ] Requested improvements are completed.
- [ ] Required approvals are received.

## 4. Before Merging

- [ ] No unresolved merge conflicts.
- [ ] Required checks pass.
- [ ] Final review is completed.
- [ ] Changes are ready to merge into the main branch.

## 5. After Merging

- [ ] Confirm the PR is successfully merged.
- [ ] Verify the changes in the main branch.
- [ ] Update project documentation if necessary.
